# Первоначальные 8 правил расходов

`scripts/seedClassificationRules.ts` — отдельный операторский скрипт. Он не
импортируется приложением, не меняет CRUD API и не применяет классификацию к
финансовым операциям. Импорт модуля не подключается к БД. Реальный запуск в этом
PR не выполнялся.

Создаёт только отсутствующие общие правила выбранного пользователя:
Продукты/Подписки/Такси → `everyday`, Аптеки/Фастфуд/Чаевые/Подарки/Бар →
`irregular`. Все — `expenses`, `ordinary_expense`, `enabled: true`, без `title`.
Строки нормализует готовая модель (`trim().toLowerCase()`).

## Условия перед отдельным разрешённым запуском

- Проверить SHA сборки и получить явный ObjectId нужного существующего
  пользователя; скрипт проверяет его наличие в `users`. Никакого обхода всех
  пользователей нет.
- Оператор заранее подготавливает обычную `classification_rules` с simple
  collation и **оба** уникальных индекса из модели PR #42/43. Готовность проверяет
  существующий `classificationRuleReadiness`; autoCreate/autoIndex/buffering
  выключены, DDL/repair в скрипте отсутствует. Даже dry-run требует готовности.
- На время запуска исключить DDL, restore и удаление владельца. Проверка каталога
  не может предотвратить последующее административное удаление индекса.
- Перед записью сохранить проверенную копию существующих правил этого владельца
  и просмотреть dry-run. Использовать учётную запись с минимальными правами:
  чтение `users`, чтение правил/каталога/индексов; для записи дополнительно insert
  в `classification_rules`. Не нужны update/delete или доступ к финансовым данным.
- Безопасно задать `CLASSIFICATION_RULES_MONGODB_URI` в окружении. Скрипт не читает
  dotenv и не использует URI приложения. Не помещать секреты в аргументы/журналы.
  БД задаётся явно через `--db` (1–63 ASCII буквы/цифры/`_`/`-`, не admin/config/local);
  этот параметр выбирает БД независимо от пути URI.

## Будущий dry-run (не выполнялся)

После сборки `npm run build` задать `RULE_OWNER` (24 hex-символа) и `RULE_DB`
(точное имя согласованной БД), затем выполнить:

```sh
node dist/scripts/seedClassificationRules.js --owner "$RULE_OWNER" --db "$RULE_DB" --dry-run
```

Без последнего флага режим также dry-run. Запись возможна **только** при замене
`--dry-run` на `--confirm-write`; совместное использование и повторные/неизвестные
аргументы запрещены. Записываются только отсутствующие правила, через полную
валидацию модели и `save()` с majority write concern. Автоматического повтора нет.

Поиск существующего правила: owner + expenses + нормализованная category +
отсутствующий/null title (тот же общий ключ уникального индекса). Его layer,
enabled и даты не меняются, даже если отличаются. Правила с title — отдельные
ключи; они также не изменяются. Конкурентный duplicate-key считается пропуском
только после повторного чтения совпавшего ключа выбранного владельца.

## Результат

Одна строка JSON: `mode`, `total: 8`, `created`, `skipped`, `wouldCreate`, `errors`,
при ошибке — безопасный `errorCode`. В dry-run `created` всегда 0, `wouldCreate`
показывает план. `errors` включает не проверенные/заблокированные оставшиеся
правила после ошибки; счётчики в сумме дают 8. Существующие правила и секреты не
выводятся. Exit code 0 — все 8 проверены, 1 — ошибка/блокировка/ошибка закрытия.

После ошибки записи её исход может быть неизвестен: счётчик created включает
только подтверждённые записи, остановка не означает откат. Не повторять запись
автоматически; сначала проверить состояние новым dry-run. Частичный успех не
отменяется; повторный явный запуск пропускает уже существующие ключи. Скрипт
закрывает собственное соединение в finally.
